# 개인용 투자 분석 앱 프로젝트 계획서

> Claude Code와 함께 작업하기 위한 프로젝트 명세 및 단계별 개발 계획

---

## 1. 프로젝트 개요

### 1.1 목적

본 프로젝트는 **개인 학습용** 투자 분석 도구를 개발하는 것을 목적으로 한다. 시장 데이터를 자동으로 수집하고, 정의된 분석 로직과 LLM을 활용해 매수·매도 후보 종목을 도출하며, 그 근거와 반대 시나리오를 자연어로 제시한다. 사용자는 추천을 그대로 따를 수도 있고, 단순히 분석 과정을 학습 자료로 사용할 수도 있다.

**핵심 원칙**: 본 프로젝트의 성공 기준은 "수익률"이 아니라 "시장에 대한 이해도 향상"이다. 실제 자금 운용은 충분한 모의투자 검증 이후에만 고려한다.

### 1.2 목표 (단계별)

- **단기 목표 (1~2개월)**: 매일 자동으로 시장 데이터를 수집하고, 정의된 룰 기반으로 후보 종목을 뽑아내는 파이프라인 구축
- **중기 목표 (3~6개월)**: LLM 기반 근거 생성, 모의투자 트래킹, 성과 평가 시스템 완성
- **장기 목표 (6개월~)**: 실제 자금 투입을 고려할 수 있는 수준의 검증된 시스템 (사업화는 별도 검토)

### 1.3 비목표 (Out of Scope)

- 단기 트레이딩(스캘핑, 데이트레이딩) 지원
- 자동매매 실행 (당분간은 분석 및 알림만)
- 외부 사용자 대상 서비스 (개인용 한정)
- 법적 자문업 등록 필요 영역 (사업화 검토 시점에 별도 진행)

## 2. 기술 스택 권장사항

### 2.1 언어 선택: Python

**Python을 권장하는 이유**:

1. **금융·데이터 분석 생태계**: pandas, numpy, scipy, statsmodels 등 시장 데이터 처리에 필요한 라이브러리가 사실상 표준
2. **금융 데이터 API 친화적**: pykrx, FinanceDataReader, yfinance 등 한국·미국 주식 데이터 수집 라이브러리 풍부
3. **LLM 통합 용이**: Anthropic, OpenAI SDK 모두 Python이 1차 지원 언어
4. **백테스팅 프레임워크**: backtrader, vectorbt, zipline 등 검증된 도구 다수
5. **사용자의 백엔드 운영 경험과 호환**: 기존 ApiMgr/CollectMgr 운영 경험이 그대로 활용 가능

**대안 고려사항**:
- TypeScript/Node.js: 웹 UI까지 풀스택으로 통일하려면 고려 가능하나, 금융 데이터 분석 생태계가 Python 대비 빈약
- Rust/Go: 성능은 좋지만 본 프로젝트는 분석 로직이 핵심이라 개발 속도가 더 중요

## 3. 단계별 개발 계획

### Phase 1: 데이터 파이프라인 구축 (예상 1~2주)

**목표**: 관심 종목의 가격, 거래량, 재무 데이터를 매일 자동으로 수집해 DB에 적재

**작업 항목**:
1. 프로젝트 초기화 (pyproject.toml, 디렉토리 구조, 가상환경)
2. SQLAlchemy로 DB 스키마 정의
   - `stocks` (종목 마스터)
   - `daily_prices` (일봉 데이터)
   - `financial_statements` (분기·연간 재무)
   - `news_articles` (뉴스, Phase 1에서는 선택 사항)
3. 데이터 수집 모듈 작성
   - 한국 주식: `pykrx`로 시작 (무료, API 키 불필요)
   - 미국 주식: `yfinance`로 시작
4. 일일 수집 스크립트 작성 및 cron 등록
5. 수집 데이터 검증 로직 (결측치, 이상치 탐지)

**완료 기준**: 매일 새벽 자동으로 어제까지의 데이터가 DB에 쌓이며, 1주일 이상 안정적으로 동작

**Claude Code에게 지시할 때 포함할 내용**:
- "Python 3.11+, uv를 사용해 프로젝트 초기화"
- "SQLAlchemy 2.0 스타일로 모델 정의 (declarative_base 아님)"
- "pykrx로 KOSPI 200 종목의 일봉 데이터를 수집하는 스크립트 작성"
- "수집 결과를 SQLite에 upsert하는 로직 포함"

---

### Phase 2: 단일 분석 시나리오 구현 (예상 1~2주)

**목표**: 정의된 단일 매매 룰로 매일 후보 종목을 자동 추출

**작업 항목**:
1. 매매 전략을 YAML로 외부화 (코드 수정 없이 룰 변경 가능하도록)
2. 첫 전략 구현 — 예시:
   - **밸류 + 모멘텀 결합**: PER이 업종 평균 대비 30% 이하 + 최근 분기 영업이익 YoY 증가 + 20일 이평선 상회
   - **기술적 단순 룰**: 거래량이 20일 평균의 2배 이상 + 종가가 전일 종가보다 3% 이상 상승
3. 스크리닝 결과를 DB의 `screening_results` 테이블에 저장
4. 매일 오전 스크리닝 실행 후 결과 요약 출력 (CLI 또는 텍스트 파일)

**완료 기준**: 매일 후보 종목이 자동으로 추출되어 기록되며, 한 달간의 결과를 되돌아볼 수 있다

**중요한 학습 포인트**: 이 단계에서 **수익률을 좇지 말 것**. 단순한 룰이 얼마나 자주 틀리는지, 어떤 상황에서 어떤 식으로 틀리는지 관찰하는 것이 목적.

---

### Phase 3: LLM 기반 근거 생성 (예상 1주)

**목표**: 후보 종목에 대해 "왜 매력적인가"와 "어떤 시나리오에서 틀릴 수 있는가"를 LLM이 자연어로 생성

**작업 항목**:
1. Anthropic SDK 설치 및 API 연동
2. 프롬프트 템플릿 작성 (확증편향 방지 위해 반대 논거 강제 생성)
3. 입력 데이터 구조화 — 종목의 최근 가격 추이, 재무 지표, 업종 데이터, 관련 뉴스 헤드라인을 LLM에 전달
4. 출력 포맷 정의 (JSON):
   ```json
   {
     "ticker": "005930",
     "thesis": "매수 논거 요약",
     "supporting_factors": ["..."],
     "risks": ["..."],
     "invalidation_scenario": "이 판단이 틀린 것으로 판명될 조건",
     "suggested_entry_range": "...",
     "suggested_stop_loss": "...",
     "confidence_level": "low/medium/high"
   }
   ```
5. 토큰 사용량 모니터링 및 비용 로깅

**완료 기준**: 매일 후보 종목 각각에 대해 균형 잡힌 분석 노트가 자동 생성됨

**주의**: LLM 출력은 절대로 "맞는 답"이 아니라 "사고의 출발점"으로 사용해야 한다. 프롬프트에 이 점을 명시.

---

### Phase 4: 모의투자 트래킹 (예상 1주)

**목표**: 실제 돈은 한 푼도 넣지 않고, 시스템의 추천대로 매매했을 경우의 가상 성과를 추적

**작업 항목**:
1. `paper_portfolio` 테이블 설계 (현금 잔고, 보유 종목, 거래 내역)
2. 매수·매도 로직 구현 — 시스템이 추천을 내면 다음 거래일 시가에 매수했다고 가정
3. 손절·익절 자동 실행 로직 (가격 도달 시 가상 청산)
4. 성과 지표 계산
   - 누적 수익률
   - 시장 대비 초과 수익 (KOSPI 또는 S&P 500 벤치마크)
   - 최대 낙폭 (MDD)
   - 샤프 비율
   - 승률 및 손익비
5. 정직한 성과 보고 — 체리피킹 방지 위해 모든 추천의 결과를 빠짐없이 기록

**완료 기준**: 최소 1개월 이상 모의투자가 누적되고, 정직한 성과 리포트가 생성됨

---

### Phase 5: UI 및 일상 사용 (예상 1~2주)

**목표**: 매일 사용 가능한 형태의 인터페이스 구축

**작업 항목**:
1. Streamlit으로 빠르게 MVP UI 구축 (이후 필요 시 FastAPI + 프론트로 전환)
2. 주요 화면:
   - **오늘의 후보**: 매일 스크리닝된 종목 + LLM 분석 노트
   - **모의 포트폴리오**: 현재 보유 종목 + 누적 성과
   - **종목 상세**: 차트 + 재무 지표 + 분석 이력
   - **전략 백테스트**: 과거 데이터로 현재 룰의 성과 시각화
3. 모바일에서도 볼 수 있도록 반응형 고려 (Streamlit은 기본 지원)
4. 알림 기능 — 손절가 도달, 신규 후보 등장 시 (이메일 또는 텔레그램 봇)

**완료 기준**: 매일 아침 5분만 봐도 시장 상황과 후보 종목, 본인 모의 포트폴리오를 파악할 수 있음

---

### Phase 6 이후: 그때 결정하기

여기까지 오면 3~6개월이 지나 있을 것이며, 그때쯤 본인이 직접 무엇을 더 만들고 싶은지 명확해진다. 미리 계획하지 말 것. 가능한 방향:
- 다중 전략 동시 운용 및 앙상블
- 백테스트 프레임워크 본격화 (vectorbt 등)
- 사업화 검토 시 법무 자문 진행
- 자동매매 (충분한 검증 후에만)

## 4. Claude Code 협업 가이드

### 4.1 효과적인 작업 분해 방식

Claude Code에게 한 번에 너무 큰 작업을 시키지 말 것. 위 Phase를 더 잘게 쪼개서 다음과 같은 단위로 지시한다:

- ✅ "Phase 1의 1~2번 작업: pyproject.toml과 디렉토리 구조 생성, SQLAlchemy 모델 정의"
- ❌ "Phase 1 전체를 만들어줘"

### 4.2 매 작업마다 명시할 것

- **목적**: 이 코드가 왜 필요한가
- **입력/출력**: 함수의 시그니처와 데이터 형태
- **제약**: 사용 라이브러리, 코딩 스타일 (예: 타입 힌트 필수)
- **테스트**: 어떻게 검증할 것인가 (간단한 pytest 또는 수동 확인 절차)

### 4.3 코드 품질 기준

- 모든 함수에 타입 힌트
- 외부 API 호출은 재시도·예외 처리 필수
- 비밀 정보(API 키)는 `.env`로 관리, 코드에 하드코딩 금지
- 데이터베이스 스키마 변경은 alembic 마이그레이션으로 관리 (Phase 2 이후)
- 주요 로직에 docstring

### 4.4 검토 체크리스트 (코드 받을 때마다)

- [ ] 외부 API 응답 형태가 변할 가능성에 대비했는가
- [ ] 시장 휴장일·결측 데이터를 처리하는가
- [ ] 시간대(timezone) 처리가 명확한가 (특히 미국 주식)
- [ ] 재무 데이터의 발표 시점과 적용 시점을 구분하는가 (look-ahead bias 방지)
- [ ] 비용이 드는 API 호출(LLM, 유료 데이터)에 캐싱이 있는가

## 5. 위험 요소 및 자기 룰

본 프로젝트를 진행하면서 빠지기 쉬운 함정들과 미리 정해두는 자기 규칙.

### 5.1 기술적 함정

- **과적합**: 백테스트 결과가 좋다고 실전이 좋은 것 아님. 항상 out-of-sample 검증
- **생존자 편향**: 현재 상장 종목으로만 백테스트하면 결과가 부풀려짐. 가능하면 상폐 종목 데이터도 포함
- **Look-ahead bias**: 미래 시점의 데이터를 과거 분석에 사용하지 않도록 주의 (예: 분기 실적은 발표일 이후에만 사용 가능)
- **거래 비용 무시**: 수수료·세금·슬리피지 반드시 모의투자에 반영 (한국 주식 매도 시 거래세 0.18% 등)

### 5.2 심리적 함정

- **"내가 발견한 패턴" 환상**: 짧은 기간의 좋은 성과는 거의 운. 최소 6개월~1년의 페이퍼 트레이딩 후에야 평가 가능
- **확증편향**: LLM 출력 중 매수 논거만 보고 반대 논거 무시하지 않기. UI에서 두 영역을 동등한 비중으로 보여주기
- **실시간 개입 충동**: "지금 시장이 이상하니까 시스템 멈추고 내가 판단해야겠다"는 순간이 가장 위험. 룰은 룰대로 돌아가게 둘 것

### 5.3 미리 정해두는 자기 룰

> 아래 룰을 README나 코드 주석에 박아두고, 코드를 만질 때마다 보이게 한다.

1. **실제 자금 투입 조건**: 최소 6개월 모의투자 + 누적 수익률이 벤치마크를 의미 있게(*) 이긴 후에만 고려
   - (*) "의미 있게"의 정의: 연환산 초과수익 5% 이상이면서 샤프 비율 1.0 이상
2. **첫 실전 자금 한도**: 잃어도 일상에 영향 없는 금액에서 시작 (구체적 금액은 본인이 정함)
3. **시스템 중단 조건**: 모의투자 기준 MDD가 -25%를 초과하면 운영 중단하고 원인 분석
4. **비공개 원칙**: 본인 외 누구에게도 추천 결과를 공유하지 않음 (사업화 검토 전까지)
5. **공부 우선 원칙**: "이 코드를 짜면서 내가 무엇을 배웠는가"를 매주 한 줄로 기록
